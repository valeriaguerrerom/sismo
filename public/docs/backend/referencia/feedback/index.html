    Buzón de contacto¶

    Recepción de mensajes de contacto con control anti-spam (honeypot y límite por IP) y consentimiento de tratamiento de datos cuando se incluye un correo.

    feedback ¶

    Formulario de contacto "Escríbenos" (página Acerca de).

    Endpoint

    POST /api/feedback — recibe un mensaje del formulario y lo guarda en la tabla feedback_messages usando el cliente de servicio del backend.

    Seguridad y anti spam (todo del lado del servidor): - Valida el tipo (sugerencia | error | datos | otro), la longitud del mensaje (1..1000) y el formato del correo si se envía. - Campo trampa (honeypot): si llega con contenido, se responde OK sin guardar nada (el bot cree que tuvo éxito). - Autorización de datos (Ley 1581) obligatoria cuando se deja correo. - Límite de envíos por IP: 3 por minuto y 20 por día (en memoria del proceso; suficiente para un despliegue de un solo worker). - Si el visitante tiene sesión, el id del usuario se toma del token verificado contra Supabase, NUNCA de lo que envíe el navegador.

    La escritura la hace un cliente de servicio del backend, autenticado con una variable secreta configurada en el servidor, que salta las RLS. La tabla NO permite INSERT desde anon ni authenticated (ver la migración 20260926_feedback_backend_only.sql).

    Bases: BaseModel

    Cuerpo del formulario de contacto.

    create_feedback(request: Request, body: FeedbackIn = Body(...), authorization: str | None = Header(default=None)) ¶

    Recibe y guarda un mensaje del formulario "Escríbenos".

    Parameters:

    Name Type Description Default
    request Request

    Petición (para obtener la IP y aplicar el rate limit).

    		 required
    body FeedbackIn

    Tipo, mensaje, correo opcional, consentimiento y honeypot.

    		 Body(...)
    authorization str | None

    Encabezado Bearer opcional; si es válido, asocia el usuario autenticado.

    		 Header(default=None)

    Returns:

    Type Description

    {"ok": True} si el mensaje se guardó (o si el honeypot lo descartó

    silenciosamente).

    Raises:

    Type Description
    HTTPException 400

    tipo inválido, mensaje vacío o muy largo, correo mal formado, o falta la autorización de datos cuando hay correo.
    HTTPException 429

    se superó el límite de envíos por IP.
    HTTPException 503

    el servidor no tiene configurada la clave de servicio.
