    Pruebas por sprint¶

    La plataforma cuenta con pruebas automatizadas en tres herramientas:

    • Vitest — pruebas unitarias del frontend.
    • pytest — pruebas del backend.
    • Playwright — pruebas de extremo a extremo (navegador).

    Las pruebas se organizan por sprint (1 a 16), cada uno asociado a una o varias historias de usuario (HU). Esta página resume cómo volver a ejecutarlas.

    Preparación (una sola vez)¶

    # Dependencias
pnpm install

# Para las pruebas de extremo a extremo (Playwright):
# 1) Compilar el frontend
pnpm build
# 2) Servir el frontend en el puerto 8080 (dejar la terminal abierta)
pnpm exec vite preview --port 8080 --host
# 3) En otra terminal, levantar el backend en el puerto 8000
cd backend ; py -m uvicorn main:app --port 8000

    Entorno de las pruebas de extremo a extremo

    Playwright se ejecuta en Chromium y en serie (--project=chromium --workers=1). Las pruebas son de lectura o escriben únicamente datos de la propia cuenta de prueba, que luego se limpian. Algunos casos se omiten a propósito (flujos que requieren OAuth real, envío de correo real, una cuenta administradora o escrituras en producción) y quedan documentados como omitidos en la evidencia de cada sprint.

    Cómo ejecutar un sprint¶

    Cada sprint se corre con uno o varios de estos comandos, según las herramientas que use. Ejemplos representativos:

    pnpm exec vitest run src/lib/sprint04.test.ts --reporter=verbose

    cd backend ; py -m pytest tests/test_sprint04.py -v

    $env:E2E_ENV='local'; pnpm exec playwright test e2e/sprint03.spec.ts --project=chromium --workers=1

    Sustituye el número de sprint en el nombre del archivo para ejecutar otro sprint. Los sprints que combinan herramientas se corren con un comando por cada una.

    Correr todas las pruebas¶

    # Vitest (todo el frontend)
pnpm exec vitest run

# pytest (todo el backend)
cd backend ; py -m pytest -q

    Los casos omitidos lo son por restricciones del entorno de prueba (sin un servicio de datos de pruebas aparte, sin OAuth/SMTP reales automatizables y sin cuenta administradora), no por fallos. Cada omisión queda justificada en la evidencia del sprint correspondiente.
